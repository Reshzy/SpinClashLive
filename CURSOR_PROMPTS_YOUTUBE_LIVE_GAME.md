# Cursor Implementation Prompts — YouTube Live Prediction Game

Use these **five prompts in order** in Cursor Agent mode. Copy one complete fenced prompt per milestone. Let Cursor implement and verify it before sending the next. A milestone can span several agent continuations; five prompts does not mean five individual tool actions.

Place `MASTER_YOUTUBE_LIVE_GAME.md` in the project root and keep this file beside it. Optionally place the supplied visual reference at `docs/references/image.png`. Each prompt reads the master rather than relying on previous chat context. Use the same project repository throughout. Commit milestones locally when appropriate, preserving any existing user changes; do not push or deploy without authorization.

If Cursor reaches a context limit, ask it to continue the current prompt using `docs/PROGRESS.md`. Do not move on while a prerequisite is failing. If a real Google/Windows/OBS check is unavailable, finish the implementation, record that specific external check as blocked, and continue work that does not depend on it. Never invent test results.

## How to use these files

1. Create/open the project folder in Cursor and add both Markdown files.
2. Use Agent mode and paste Prompt 1; let it complete implementation and checks.
3. Continue with Prompts 2–5 in order, keeping the progress files in context.

The five milestones cover setup, game correctness, integration, security, desktop UI, stream design, testing, capacity evidence, packaging and operations. Their internal substeps are intentional: they keep the prompt count low without compressing away necessary work.
